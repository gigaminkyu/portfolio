# 오류·제약사항 — 빈틈(BinTeum)

> 매뉴얼 요건: **비개발자가 매뉴얼만 보고 설치·실행**할 수 있어야 하고, 오류 시 개별 연락은 없습니다.
> 그래서 막힐 지점을 미리 표로 만들고, **모든 오류를 "동작하는 결과"로 바꾸는 폴백**을 넣었습니다.

---

## 1. 설치·실행 오류 (FAQ)

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | `python3: command not found` / `'python'은(는) 내부 또는 외부 명령이 아닙니다` | 파이썬 미설치 또는 PATH 미등록 | python.org(Windows는 설치 시 "Add Python to PATH" 체크) |
| 2 | `파이썬 3.10 이상이 필요합니다. 현재: 3.8.x` | 버전 미달 | 3.10+ 설치 또는 `PYTHON=python3.11 ./run.sh` |
| 3 | `Permission denied: ./run.sh` | 실행 권한 없음 | `chmod +x run.sh` 또는 `bash run.sh` |
| 4 | `OSError: [Errno 98] Address already in use` | 8000 포트 사용 중 | `./run.sh --port 8080` |
| 5 | 화면에 `데이터 없음` | `data/snapshot/` 누락 | `python3 -m binteum snapshot` 실행 또는 ZIP 재압축 해제 |
| 6 | 브라우저가 안 열림 | 서버 미기동/차단 | 콘솔에 주소가 찍혔는지 확인 → 직접 주소 입력 |
| 7 | 결과 카드가 비어 보임 | 종료 시각이 이미 지난 시각 | 종료 시각을 미래(예: 18:00)로 바꿔 다시 실행 |
| 8 | 한글이 깨짐(터미널) | 콘솔 인코딩 | `export PYTHONIOENCODING=utf-8` (Windows: `chcp 65001`) |

## 2. 데이터·네트워크 관련

| 증상 | 원인 | 동작·해결 |
|---|---|---|
| `허브 실호출 403` / "Web firewall" 페이지 | 센터·데이터센터 IP에서 허브 WAF 차단 | **정상 동작으로 처리**됩니다. 스냅샷으로 자동 폴백, 화면 배지로 안내. 실시간이 필요하면 `fetch`를 사용자 네트워크에서 실행 |
| `614 API 502` | 대회 게시판에도 신고된 서버 오류 | `P_bus` 항 제외 + **가중치 자동 재정규화**(0.45/0.25/0.10). 화면에 "버스 데이터 없음 → 제외" 표시 |
| `허브 실호출 400` | 파라미터명 차이(기간 파라미터) | `python3 -m binteum doctor` 로 확인. 수정 지점은 `src/binteum/data.py`의 `_query_params` 한 곳 |
| `401/403(키 오류)` | 키 미설정·오타·만료 | 재시도하지 않고 즉시 폴백(같은 결과). 키를 다시 확인 |
| 외부 도메인 전면 차단(센터 PC) | 행안부 차단 키워드·방화벽 | `./run.sh --offline` — 지도 타일·LLM·허브 모두 미사용, 스냅샷만으로 전 기능 동작 |
| `LLM 429/타임아웃` | 한도 초과·네트워크 | **템플릿 문장으로 폴백**. 결과는 동일하며 `narrative_source: template` 로 표시 |
| `환각 가드: 근거 없는 숫자` | LLM이 데이터에 없는 수치를 씀 | 응답 폐기 후 템플릿 사용(의도된 동작) |

## 4. 폴백 체인 (요약)

```
[583/591/614/579/618]
   └ 실시간 API ─실패→ 파일 캐시 ─없음→ 수집 스냅샷 ─없음→ 동봉 스냅샷 ─없음→ 결측(항 제외)
[LLM]        사용 가능? ─아니오/실패→ 템플릿 문장
[지도]       타일 미사용(SVG 도식) → 차단과 무관
[계획]       후보 없음 → 완화 규칙 1회(이동 상한 확대) → 그래도 없으면 안내 문구
[Critic]     위반 → 블랙리스트 + 1회 재계획 → 남으면 그대로 노출(숨기지 않음)
```

## 5. 로그·진단

- `python3 -m binteum doctor` — 파이썬 버전, LLM/키 상태, 카탈로그 규모, 데이터셋별 행수·기준일, 스냅샷 출처
- `out/traces/<run_id>.jsonl` — 모든 단계의 이벤트(`pipeline_start`, `tool_call`, `hub_http`, `critic_reject`, `run_end`)
- `out/runs/<run_id>.json` — 결과 전문(문제 재현 시 이 파일을 첨부)
- `out/verification.log` — `./demo.sh` 실행 로그(진단 + 시나리오 3종 + 백테스트)

문의 시 함께 보내면 좋은 것: `doctor` 출력, `out/verification.log`, 문제가 된 `out/runs/*.json`.
