## 2. 수집 방법 — 이중 모드

| 순서 | 소스 | 조건 | 화면 표기 |
|---|---|---|---|
| 1 | 허브 Open API 실호출 | `JEJU_DATA_HUB_KEY` 설정 + `--offline` 아님 | `실시간 허브 API` |
| 2 | 로컬 파일 캐시 | 같은 파라미터 재실행 | `허브 API 캐시` |
| 3 | 직접 수집 스냅샷 | `python -m binteum fetch` 결과 (`data/snapshot/live/`) | `직접 수집 스냅샷` |
| 4 | **동봉 스냅샷** | 기본값 (ZIP에 포함) | `동봉 데모 스냅샷` |
| 5 | 결측 | 위 모두 실패 | 해당 항 **제외 + 가중치 자동 재정규화** |

- 인증키는 **환경변수에서만** 읽고 로그·산출물·ZIP에 남기지 않습니다(`config.hub_key()`).
- 응답 형식 4가지를 모두 처리합니다: `[...]`, `{data:[...]}`, `{items:[...]}`, `{response:{body:{items:[...]}}}`.
- 재시도: 400/401/403은 즉시 중단(재시도 무의미), 그 외 5xx·타임아웃은 최대 2회.
- **1회 응답 상한 100행**(서버 고정, `offset`/`page` 파라미터는 무시됨) → `fetch`가 `hasMore`를 보고
  **날짜 구간을 절반으로 쪼개** 재귀 호출해 합칩니다(`HUB_SPLIT_DEPTH=8`).
- 프로젝트에 **연결되지 않은 데이터셋은 403**이므로 호출하지 않고 `not_connected`로 표시한 뒤 스냅샷으로 폴백합니다
  (`config.DATASET_DATA_KEYS`). 현재 연결된 것은 **583 하나**입니다.

### 583 실측 수집 결과 (2026-11-18, `python -m binteum fetch`와 동일 절차)

| 항목 | 값 |
|---|---|
| 수집 구간 | 2026-06-24 ~ 2026-08-19 (57일) |
| 읍면동 | 43개 (제주시·서귀포시) |
| 원본 행 | 39,216행 (읍면동 43 × 일 57 × 성별 2 × 연령 8) |
| 합산 후 셀 | 2,451개 (읍면동·일별 전체/계) |
| API 호출 | 430회 (읍면동 × 6일 단위 분할) · 실패 0 |
| 저장 | `data/snapshot/live/flow.json` (ZIP 동봉, `source: jeju-datahub-live`) |
| 최신 실측일 | 2026-08-19 — 이후 구간은 허브가 아직 적재하지 않음(2026-08-26 클라우드 이전 공지) |

### 동봉 스냅샷의 성격 (중요)

| 파일 | 행수 | 성격 |
|---|---|---|
| `data/snapshot/flow.json` (583) | 1,368 | 읍면동 24개 × 57일 |
| `data/snapshot/tour.json` (591) | 2,268 | 관광지 63곳 × 36개월(2022-01~2024-12) |
| `data/snapshot/bus.json` (614) | 1,368 | 노선 24개 × 57일 |
| `data/snapshot/weather.json` (579+578) | 228 | 관측소 4곳 × 57일 |
| `data/snapshot/wifi.json` (618) | 65 | AP 65개 |

- **583은 실측 수집분**(`data/snapshot/live/flow.json`, 43개 읍면동 × 57일 = 2,451행)이고,
  나머지 591·614·579·618은 프로젝트 미연결(403)로 **합성 스냅샷**(`source: synthetic-demo`)입니다.
- 합성 파일은 스키마·결측 표기·요일효과·계절곡선을 실제와 같게 재현해 **파이프라인·화면·테스트를 검증**하기 위한 것이며,
  실측 통계가 아닙니다. 이 구분은 **화면 배지(`실측 + 일부 스냅샷`) / 결과 JSON(`data.datasets[].mode`) / 리포트 / `doctor`** 에 표시됩니다.
- 개발 환경(데이터센터 IP)은 허브가 **WAF로 차단(실측 403)** 하므로, 수집은 정상 통과되는 한국 네트워크에서 수행했습니다.
- 프로젝트에 데이터를 더 연결하면 `config.DATASET_DATA_KEYS`에 데이터키를 넣고 `python -m binteum fetch`를 한 번 실행하면
  해당 데이터셋도 실측으로 전환됩니다(코드 수정 없음).

## 3. 전처리

### 3.1 필드 정규화 (`src/binteum/fields.py`)

| 문제 | 처리 |
|---|---|
| 표기 혼재 (`baseDate` / `base_date` / `날짜`) | **별칭 우선순위 사전**으로 통일. 필드명이 달라도 파이프라인 유지 |
| 마스킹 값 (`***`, `**`) | 0이 아니라 **결측**으로 처리(0으로 넣으면 지수가 왜곡됨) |
| 천 단위 구분 (`1,234`) | 정수 변환 |
| 날짜 형식 (`2026-11-15`, `20261115`, `2026.11.15`) | `YYYYMMDD` 8자리로 통일 |
| 월 형식 (`2024-12`, `202412`) | `YYYYMM` 6자리로 통일 |

### 3.2 매핑 3종

| 매핑 | 방법 | 결과 |
|---|---|---|
| 관광지 → 읍면동 | 카탈로그 CSV의 `emd` 컬럼(수기 검수) | 63곳 → 24개 읍면동, 매핑률 **100%** |
| 관광지 → 정류소·노선 | 카탈로그 `near_routes`(수동 24개 노선) | 63곳 전부 노선 보유 |
| 관측소 → 지역 | 578 좌표와 관광지 좌표의 최근접 | 4개 관측소 자동 선택 |

### 3.3 지수 계산 (요약)

```
CI = 100 × Σ w·P / Σ w        w = {visit .45, tour .25, bus .20, weather .10}
P_visit  : 최근 8주 동일 요일유형 visitPop 백분위 (mid-rank)
P_tour   : 해당 월 관광객수 ÷ 최근 3년 동월 최대
P_bus    : 노선 수요의 동일 요일유형 백분위
P_weather: 강수·풍속 심각도 → 실내 0.5+0.5s / 야외 0.5−0.5s
결측 항은 제외 후 남은 가중치 합이 1이 되도록 재정규화
```

> `visitPop`은 **하루 동안 시간대별 방문인구를 더한 연인원**입니다(운영진 답변 확인).
> 따라서 화면·문서 어디에도 절대 인원을 표기하지 않고 **백분위만** 사용합니다.

## 4. 분석 흐름

```
583·591·614·579·578·618 → 정규화 → 매핑 → (요일유형 8주 창) 백분위 → CI(0~100)
   → Planner: 제약 필터(실내·보행·예산·영업시간·귀가 복귀) + 목적함수 3개
   → Critic: 규칙 R1~R6 → 통과 시 Reporter
   → 출력: JSON(+trace) · HTML 리포트 · 카드 문장
```

## 5. 이용조건

| 항목 | 준수 내용 |
|---|---|
| 출처 표기 | 화면·리포트·기획서에 데이터명 + 허브 ID + 제공기관 표기 |
| 개인정보 | 개인 식별 데이터 수집·저장 없음. 위치 이력 서버 저장 없음 |
| 소수 셀 | 10건 미만 값 미표시 원칙 준수(센터 반출 데이터 사용 시) |
| 재배포 | 대회 배포 xlsx 원본 2종 **ZIP·GitHub 미포함**. 스냅샷은 전처리 결과물로 포함(운영진 허용 범위) |
| API 키 | ZIP 미포함. 발급·설정 절차만 문서화(`.env.example`, README §2) |
| 이용 목적 | 비상업적 공모전 제출. 결과물 소유권은 제주빅데이터센터 귀속 규정을 따름 |
