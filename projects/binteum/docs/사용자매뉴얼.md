# 사용자 매뉴얼 — 빈틈(BinTeum)

> 여행자용 화면 사용법과, 운영·시연 담당자를 위한 절차를 함께 담았습니다.
> 설치·실행은 `README.md`를 먼저 보세요.

---

## 1. 여행자용 — 30초 사용법

1. 브라우저에서 `http://127.0.0.1:8000` 을 연다.
2. 왼쪽에서 **현재 위치(읍면동)** 를 고른다. (예: 지금 성산에 있으면 `성산읍`)
3. **종료(귀가) 시각** 을 정한다. (기본 18:00)
4. 필요하면 **동행·이동수단·실내·예산·테마**를 고른다. (안 골라도 됩니다)
5. **`빈틈 찾기`** 를 누른다. → 1초 안에 동선 3안이 나온다.

> 급하면 왼쪽 아래 **예시 시나리오 3개** 중 하나를 누르세요. 입력이 자동으로 채워지고 바로 실행됩니다.

### 결과 읽는 법

| 표시 | 의미 |
|---|---|
| **CI 37 한산** | 혼잡지수 37/100. 낮을수록 한산. 45 미만 한산 · 45~70 보통 · 70 이상 붐빔 |
| `13:50~14:40 · 50분 · 이동 10분(3.2km)` | 도착·출발, 체류, 앞 장소에서의 이동 |
| 카드 상단 `가장 한산한 순서로 5곳 · 평균 CI 41.4 · 이동 78분` | 그 안의 요약 |
| **안 A / B / C** | A=한산 우선, B=이동 최소, C=취향·실내 우선 |
| `추천` 배지 | Critic 검증을 통과한 안 중에서, 혼잡도가 비슷하면 하루를 더 알차게 쓰는 안 |
| 회색 회색 태그 `가정: 이동수단 미지정 → 렌터카 가정` | 빈틈이 임의로 정한 값. 원하면 바꿔 다시 실행 |
| 초록 배지 `실측 + 일부 스냅샷` | 지금 사용 중인 데이터 종류(실시간/실측 수집분/스냅샷) |

### "왜 여기인가" 확인하기

카드 아래 **근거 상세** 표에서 정류장별로 다음을 볼 수 있습니다.

- **사용 항(백분위)**: `visit 26% · tour 76% · bus 23% · weather 88%` — 어떤 항이 그 판단을 만들었는지
- **제외 항**: 데이터가 없어 뺀 항(예: `bus`) — 이때는 남은 항으로 가중치가 자동 재조정됨
- **기준일**: `20260819` — 데이터가 언제 것인지(허브가 마지막으로 제공한 실측일)
- **신뢰도**: `ok` / `partial`(일부 항 제외) / `low_sample`(표본 부족)

### 공유하기

- **`카톡 공유용 텍스트 복사`** → 카톡에 붙여넣기
- **`결과 JSON 내려받기`** → 근거 전체를 파일로 저장(여행 기록·검증용)

### 자주 쓰는 입력 예

| 상황 | 입력 예 |
|---|---|
| 아이와 실내 위주 | "성산인데 애 데리고 6시까지 실내 위주로" + 동행 `아이 동반` + `실내 위주로` 체크 |
| 버스 여행·예산 | "애월, 버스로 다니고 예산 3만원, 9시까지 야경" + 이동수단 `버스` |
| 부모님 모시고 | "중문, 부모님 모시고 걷기 힘드셔서 짧게" + 동행 `부모님 모시고` |
| 비 오는 날 | "지금 비 오는데 실내로" + `실내 위주로` 체크 (날씨 항이 실내 후보를 올려 줍니다) |

## 2. 운영·시연 담당자용

### 시연 순서(3분)

1. `./run.sh` → 콘솔의 `데이터 : snapshot (기준일 …)` 확인
2. 화면 상단 오른쪽 배지로 데이터 모드 확인 (`실시간` / `실측 + 일부 스냅샷` / `동봉 데모 스냅샷`)
3. 예시 시나리오 A 클릭 → 카드 3안 → 근거 표 → 지도 → 공유 버튼 순서로 보여주기
4. `python3 -m binteum doctor` 로 데이터 출처(5개 데이터셋 행수)를 한 화면에 보여주기
5. `out/traces/*.jsonl` 을 열어 Tool 호출 기록을 보여주기 (기술성 어필 포인트)

### 실데이터로 전환

```bash
export JEJU_DATA_HUB_KEY=발급받은키     # 제주데이터허브 → Open API 인증키 신청
python3 -m binteum fetch               # 5개 데이터셋 수집 → data/snapshot/live/
python3 -m binteum doctor              # 모드가 collected 로 바뀌었는지 확인
./run.sh                               # 이후 자동으로 수집분 우선 사용
```

- 수집 실패 항목은 그대로 두고 스냅샷으로 폴백합니다(서비스는 계속 동작).
- 614(버스) API는 대회 게시판에도 502 신고가 있는 데이터입니다. 실패해도 CI는 자동 재정규화됩니다.

### 스냅샷 재생성(데모용)

```bash
python3 -m binteum snapshot --ref 20260819 --seed 7
```

- `--ref`는 기준일, `--seed`는 난수 시드입니다. 같은 값이면 **완전히 같은 데이터**가 만들어집니다(재현성).
- 생성되는 데이터는 `source: synthetic-demo` 로 표기됩니다.

### 결과 파일 관리

| 위치 | 내용 | 비고 |
|---|---|---|
| `out/runs/` | 실행 JSON(전체 근거·trace 경로) | 실행마다 새 파일 |
| `out/reports/` | 독립 HTML + 마크다운 리포트 | 브라우저로 바로 열림 |
| `out/traces/` | Tool 호출 JSONL | 시각·행수·캐시·폴백·반려 기록 |
| `out/backtest/` | 백테스트 결과 | `backtest.md` |
| `var/cache/` | 허브 응답 파일 캐시 | 지워도 됨(다음에 다시 받음) |

> 오래된 실행 결과는 지워도 서비스 동작에 영향이 없습니다(`out/`, `var/` 는 산출물 폴더).

## 3. 하지 않는 일 (안내 문구)

- 예약·결제·메시지 발송: **기능이 없습니다.** 추천까지만 합니다.
- 위치·이동 이력 저장: 서버에 저장하지 않습니다. 결과 파일은 사용자 PC의 `out/` 폴더에만 남습니다.
- 개인정보 수집: 없습니다. 로그인·계정 개념이 없습니다.

화면에도 같은 문구가 표시됩니다: *"추천까지만 합니다. 예약·결제·외부 전송은 하지 않습니다."*
